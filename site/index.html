filosofia aplicada ao software

A melhor arquitetura devolve tempo para pensar.

Menos colagem entre ferramentas. Mais contexto, limites claros e tempo recuperado para o trabalho que só a sua equipe pode fazer.

01

Um runtime, menos dispersão

Transformação, orquestração, fila e scheduler no mesmo binário. Menos peças para coordenar; mais atenção para o domínio que sua equipe realmente conhece.

simplicidade

02

Fila que preserva contexto

Eventos, dependências e retries persistem sem virar mais uma camada invisível para você operar.

continuidade

03

Ritmo com propósito

Cron, eventos e dependências são resolvidos por um scheduler que entende a jornada inteira do workflow.

disciplina

04

Visibilidade é uma virtude

Uma interface direta para observar execuções, logs, estados e decisões — sem decorar o que precisa ser compreendido.

clareza
ingest.yaml 
name: ingest

steps:
  - id: transform
    image: brevis/etl:1.4
    run: transform postgres

O workflow inteiro é um arquivo versionável. Revisar um pipeline vira revisar um diff.

Declarativo por escolha, não por moda. O que o arquivo diz é o que o runtime faz — e o que ele não diz, o runtime não inventa.

de brevitate vitae

Não é que temos pouco tempo. É que perdemos muito dele.

A máxima de Sêneca guia a pergunta por trás do brevis.sh: quais complexidades realmente merecem o tempo de uma equipe? Cada workflow executa em pods isolados para que falhas, versões e dependências tenham limites claros.

01

imagem por etapa

Cada passo declara o runtime de que precisa. Trocar a versão de um não obriga a mexer nos outros.

02

logs por execução

A saída pertence ao run que a produziu. Investigar uma falha não é reconstruir um contexto perdido.

03

retries persistentes

A tentativa sobrevive ao processo. Uma reinicialização não apaga o que já se sabia sobre o trabalho.

04

isolamento de dependências

O que uma etapa carrega não vaza para as vizinhas. Limite claro é o que torna a falha legível.

perguntas frequentes

Comece com o essencial.

O brevis.sh é realmente 100% open source?

Sim. O runtime completo é aberto para leitura, uso, adaptação e contribuição da comunidade.

O que a referência a Sêneca significa para o projeto?

De Brevitate Vitae inspira uma engenharia mais intencional: reduzir a complexidade que consome tempo e preservar espaço para trabalho com propósito.

Como funciona o isolamento dos pods?

Cada etapa do workflow executa como um pod próprio com sua imagem, mantendo dependências e contexto de execução separados.

Qual é a relação com a Aretê Academy?

O brevis.sh é um projeto do grupo Aretê Academy, que aproxima grandes ideias da filosofia dos desafios reais da construção de software.
