O Problema

Orquestração de dados exige múltiplas ferramentas. Você escolhe entre Airflow (pesado), dbt (sem orquestração), Kestra (complexo), LeoFlow (incompleto). E ainda assim tem que montar a interface você mesmo.

🗂️

dbt

Excelente para transformação. Não faz orquestração, nem agendamento, nem fila.

⚙️

Airflow

Orquestração poderosa, mas pesada. UI complexa. Curva de aprendizado brutal.

🔗

Kestra

Promete unificar. Acaba sendo mais uma dependência. Segue complexo.

📦

LeoFlow

Focado em fila. Não traz transformação integrada. Você segue montando peças.

A Solução: Bravis

Um binário único, escrito em Go, que substitui dbt + Airflow + LeoFlow por uma arquitetura moderna: transformação, orquestração, fila, scheduler e UI integrados.

⚙️

Transform

Transformação inspirada em dbt. Modelos, testes, materialização integrados.

🔀

Orchestrate

DAGs em YAML. Scheduler com cron. Fila persistente. Backfill automático.

👁️

Observe

UI server-rendered. DAG ao vivo. Métricas, gráficos e controle completo.

Características

⚡

Um Binário Único

Escrito em Go. Executa em Kubernetes, Docker ou localmente. Sem dependências externas.

📄

Workflows em YAML

Declarativo, versionável, humano-legível. Sem UI complexa para definir jobs.

☸️

Kubernetes-Native

Cada passo vira um pod. Seu runtime, sua imagem, sua responsabilidade.

⏱️

Scheduler + Fila

Dois laços independentes. Cron, backfill, retry automático. Um falha, outro segue.

📦

Imagens Otimizadas

5.8 MB em Go, 118 MB em Python, 620 MB em dbt. Observabilidade integrada.

🎨

Marca Branca

Customize título, frase e paleta. Seus dados, sua marca, nossa orquestração.

Escalabilidade em Kubernetes

Bravis é desenhado para EKS. Cada passo de um workflow vira um pod independente. Você não tem workers genéricos esperando trabalho—o trabalho traz seu próprio runtime.

📦

Isolamento Total

Cada passo roda em seu próprio container. Sem crosstalk, sem contaminação de estado.

📈

Escala Horizontal

Kubernetes distribui pods conforme necessário. Carga spike? Novos pods sobem automaticamente.

📊

Observabilidade Nativa

Logs, métricas, traces. Seu cluster já coleta. Bravis integra sem overhead.

Primeiros Passos

1. Instalar:

$ go install github.com/AreteAcademy/bravis@latest

2. Validar um workflow (sem banco):

$ bravis validate examples/hello.yaml

3. Executar agora:

$ bravis run examples/hello.yaml

4. Publicar e agendar:

$ bravis publish examples/hello.yaml
$ bravis scheduler --concurrency 5

Exemplo: Um Workflow Real

Tudo é YAML. Simples. Declarativo.

name: diario schedule: "0 8 * * *" # 8AM todo dia concurrency: 1 params: - name: load_full type: boolean default: "false" steps: - id: bronze run: dbt build --select bronze+ - id: silver run: dbt build --select silver+ depends_on: [bronze] - id: gold run: dbt build --select gold+ depends_on: [silver]
